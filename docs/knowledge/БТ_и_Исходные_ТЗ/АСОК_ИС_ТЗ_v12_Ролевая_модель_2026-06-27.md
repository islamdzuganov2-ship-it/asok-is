# АСОК ИС — ТЗ v12: Ролевая модель

> Канонизирует разрозненные роли (в коде/заметках были TEST_ANALYST, QUALITY_MANAGER, ADMIN,
> CTO, CEO, CIO, EXECUTIVE) в **три**. Связь: [[АСОК_ИС_ТЗ_v11_Дашборд_Отчёты_БазаРисков_2026-06-26]],
> [[АСОК_ИС_Бэклог_Безопасность_S7-S10-S11]]. Полная версия — `docs/ТЗ_Ролевая_модель_v12.md`.

## Три канонические роли
| Код | Подпись | Кто | Уровень |
|-----|---------|-----|---------|
| `ADMIN` | **Топ-менеджмент** | ЛПР верхнего уровня; решения по мерам, приоритеты, ресурсы; без привязки к титулу (CIO/CTO/CEO/директор). | Стратегический |
| `QUALITY_MANAGER` | **Менеджер по качеству** | проф. суждения, постановка мер, контроль выполнения, база рисков. | Тактический |
| `TEST_ANALYST` | **Аналитик** | ввод val_a/val_b, Excel, расчёты. | Операционный |

Легаси CTO/CEO/CIO/EXECUTIVE → приравнены к **Топ-менеджмент**.

## Матрица прав (ключевое)
- Управленческий дашборд — только Топ-менеджмент; менеджерский — Менеджер по качеству; аналитический — все.
- Ввод метрик (val_a/val_b) — Аналитик (C·U), менеджер/топ — чтение.
- Проф. суждение и постановка меры — Менеджер по качеству.
- Решение по мере (одобрить/отклонить + коммент.) и смена ответственного/срока — Топ-менеджмент.
- Контроль выполнения (выполнено/не выполнено + обязательный коммент.) — только Менеджер по качеству.
- База рисков — запись QM/ADMIN, чтение всем.

## SoD-инварианты
Мера: создаёт менеджер → решает топ-менеджмент (не сам себе) → менеджер отчитывается о выполнении →
топ-менеджмент видит статус техдолга.

## Контур
Аналитик (данные) → Менеджер по качеству (суждение+мера) → Топ-менеджмент (решение) →
Менеджер по качеству (выполнение) → Топ-менеджмент (контроль/burndown).

## Применённые улучшения
канонизация в 3 роли + маппинг легаси · централизованные подписи ролей · усилённый SoD ·
нейминг верхнего уровня без должности («Топ-менеджмент»).

## На будущее
разделить ADMIN на «Топ-менеджмент» + «Системный администратор» · роль «Ответственный исполнитель» ·
журнал ИБ-событий по ролям (S10) · LDAP/SSO-маппинг.

## Аддендум 2026-06-30 — SoD по мерам качества (проверено и усилено QA)

> Требование пользователя: согласование работ по мерам — только `ADMIN`; закрывать меры —
> только менеджер по качеству. Требование уже соответствовало матрице прав v12 (§3); ниже —
> уточнение и фиксация enforcement в коде.

- **Согласование меры (одобрить/отклонить) — ТОЛЬКО `ADMIN` (Топ-менеджмент).**
  Enforced: `frontend/src/components/MeasureDecisionModal.tsx` (`canDecide`),
  `frontend/src/pages/ExcelReportsPage.tsx` (колонка «Решение»). Не-ADMIN видят
  «Ожидает решения топ-менеджмента» без кнопок.
- **Закрытие меры (контроль выполнения, обязательный комментарий) — ТОЛЬКО `QUALITY_MANAGER`.**
  Enforced: `MeasureDecisionModal.tsx` (`canReportExecution`). До правки кнопки «Одобрить/Отклонить»
  показывались любой роли — это был дефект (DEF-11), устранён.
- SoD-инвариант: согласующий (ADMIN) не отчитывается о выполнении; закрывающий (QM) не принимает
  решение. Меры — фронтовый governance-слой (Redux+localStorage), гейтинг на UI; при выносе в
  backend продублировать `require_role`.
