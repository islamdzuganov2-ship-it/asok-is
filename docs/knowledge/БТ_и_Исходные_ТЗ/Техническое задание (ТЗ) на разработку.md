# 📑 Техническое Задание: АСОК ИС

## 1. Общее описание системы

### 🎯 Цель проекта
Разработка веб-платформы для ежеквартальной оценки качества информационных систем банка. Система заменяет ручной сбор данных в Excel, автоматизирует расчет 28 метрик по 9 характеристикам (на основе методики МК_8.1), фиксирует профессиональные суждения экспертов и генерирует отчетность.

### 👥 Роли пользователей (RBAC)
| Роль | Описание | Доступ |
| :--- | :--- | :--- |
| `TEST_ANALYST` | Сбор и верификация данных | Ввод `A`/`B`, прикрепление артефактов (Jira/Confluence). |
| `QUALITY_MANAGER` | Анализ и корректировка | Просмотр расчетов, внесение `Expert Review`, формирование рисков. |
| `CTO/CEO` | Управление (Read-Only) | Дашборды, тепловые карты, AI-инсайты. |
| `ADMIN` | Администрирование | Управление справочниками, пользователями, Feature Flags. |

## 3. База данных (Database Schema)

> [!IMPORTANT] Ключевые решения по БД
> *   **Generated Columns:** ❌ Не используются для `calculated_x` (расчет только в Python).
> *   **Soft Delete:** ✅ Реализовано (`is_deleted`, `deleted_at`).
> *   **Audit Log:** ✅ Все изменения пишутся в `audit_log`.

### 📊 Основные таблицы

#### 1. `systems` (Реестр ИС)
```sql
CREATE TABLE systems (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(255) NOT NULL,
  code VARCHAR(50) UNIQUE,
  status_lc VARCHAR(50) NOT NULL, -- 'ОЭ', 'ПЭ', 'Тестирование'
  criticality_class VARCHAR(50) NOT NULL, -- 'MISSION CRITICAL', 'BUSINESS CRITICAL', 'BUSINESS OPERATIONAL'
  owner VARCHAR(255),
  is_active BOOLEAN DEFAULT true,
  -- Soft Delete
  is_deleted BOOLEAN DEFAULT false,
  deleted_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

#### 2. `metric_catalog` (Справочник метрик)
```sql
CREATE TABLE metric_catalog (
  id INTEGER PRIMARY KEY, -- 1..28
  characteristic VARCHAR(100) NOT NULL, -- Напр. 'Надежность'
  subcharacteristic VARCHAR(100) NOT NULL, -- Напр. 'Доступность'
  formula_type VARCHAR(20) NOT NULL, -- 'DIRECT' (A/B) или 'INVERSE' (1-A/B)
  description TEXT,
  is_active BOOLEAN DEFAULT true
);
```

#### 3. `assessment_periods` (Периоды оценки)
```sql
CREATE TABLE assessment_periods (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  system_id UUID REFERENCES systems(id),
  period VARCHAR(20) NOT NULL, -- 'Q1-2026'
  status VARCHAR(20) DEFAULT 'DRAFT', -- 'DRAFT', 'IN_PROGRESS', 'COMPLETED'
  created_by UUID,
  created_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(system_id, period) -- Защита от дублей
);
```

#### 4. `assessment_values` (Значения метрик)
> [!NOTE]
> Расчет `calculated_x` выполняется на Backend. В БД сохраняется готовое значение.
```sql
CREATE TABLE assessment_values (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  period_id UUID REFERENCES assessment_periods(id),
  metric_id INTEGER REFERENCES metric_catalog(id),
  val_a NUMERIC(10,2),
  val_b NUMERIC(10,2),
  calculated_x NUMERIC(4,2), -- Результат расчета (0.00 - 1.00)
  quality_level VARCHAR(50), -- 'Высокий', 'Средний', 'Низкий', 'Невозможно измерить', 'Н'
  expert_comment TEXT,
  artifact_links JSONB, -- ["https://jira/..."]
  data_source VARCHAR(20) DEFAULT 'MANUAL', -- 'MANUAL', 'EXCEL', 'JIRA'
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

#### 5. `expert_judgments` (История профессионального суждения)
> [!WARNING] Append-Only
> Эта таблица хранит историю изменений. Старые записи не удаляются.
```sql
CREATE TABLE expert_judgments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  assessment_value_id UUID REFERENCES assessment_values(id),
  original_level VARCHAR(50),
  adjusted_level VARCHAR(50) NOT NULL,
  justification_text TEXT NOT NULL, -- Обязательное поле
  linked_risk_task VARCHAR(500),
  created_by UUID,
  created_at TIMESTAMP DEFAULT NOW()
);
```

## 4. Бизнес-логика и Метрики

### 🧮 Алгоритм расчета (Python)
Логика вынесена в отдельный сервис `CalculationEngine`.

```python
def calculate_metric(a: float, b: float, formula_type: str) -> dict:
    if b == 0:
        return {"x": 0.0, "level": "Невозможно измерить"}
    
    raw_x = (1 - (a / b)) if formula_type == "INVERSE" else (a / b)
    
    # Clamp 0..1
    x = max(0.0, min(1.0, raw_x))
    
    level = (
        "Высокий уровень" if x >= 0.81 else
        "Уровень выше среднего" if x >= 0.61 else
        "Средний уровень" if x >= 0.41 else
        "Уровень ниже среднего" if x >= 0.21 else
        "Низкий уровень"
    )
    
    return {"x": round(x, 4), "level": level}
```

### 📉 Группы характеристик (28 метрик)
1.  **Функциональная пригодность:** Покрытие требований (ТЗ vs Реализация).
2.  **Совместимость:** Интеграция с другими ИС.
3.  **Надежность:** Коррекция ошибок, Доступность (SLA), Восстановление (RTO), Бэкапы.
4.  **Пригодность для обслуживания:** Релизы (план/факт), Микросервисы, Мониторинг.
5.  **Тестируемость:** Автотесты, Заглушки, Виды тестирования, Среда.
6.  **Переносимость:** Время установки релиза.
7.  **Эффективность:** Пропускная способность, Время отклика.
8.  **Безопасность:** Аутентификация, Ролевая модель.
9.  **Удобство использования:** Руководство пользователя.

### 📝 Excel Импорт (Fallback)
Так как интеграции с мониторингом отключены, основным источником данных является загрузка `.xlsx`.
*   **Эндпоинт:** `POST /api/v1/excel/upload`
*   **Логика:** Валидация структуры -> Парсинг `A`/`B` -> Батчевая запись в БД -> Пересчет.

## 6. API Endpoints (FastAPI)

### 🔐 Auth
*   `POST /api/v1/auth/login` — Вход (JWT: 15m / 7d). В демо: `demo`/`demo123`.

### 🏢 Systems & Assessments
*   `GET /api/v1/systems` — Список ИС с фильтрацией.
*   `POST /api/v1/assessments` — Создание периода (Q1-2026).
*   `GET /api/v1/assessments/{id}` — Получить данные оценки.

### 📊 Metrics & Input
*   `PUT /api/v1/metrics/{id}` — Сохранение `val_a`, `val_b` (триггерит пересчет на сервере).
*   `POST /api/v1/expert-review` — Внесение корректировки (сохраняется в историю).

### 📥 Export
*   `GET /api/v1/reports/{id}/xlsx` — Скачивание аттестационного листа.
*   `GET /api/v1/reports/{id}/json` — Получение сырых данных.

### ⚙️ Промпт
```text
Ты — технический директор банка. 
Проанализируй комментарии менеджеров по качеству за период {period} для ИС "{system_name}": 
{comments}

Сформируй краткий управленческий вывод (2-3 предложения), объясняющий причину отклонения показателей качества. 
Используй строгий деловой стиль. Не используй маркеры или списки.
```

### 🛡️ Валидация AI
Перед сохранением ответа в БД проверяется:
1.  Длина > 50 символов.
2.  Отсутствие слов-маркеров ошибок (`error`, `timeout`, `undefined`).
3.  Retry до 3 раз при неудаче.
