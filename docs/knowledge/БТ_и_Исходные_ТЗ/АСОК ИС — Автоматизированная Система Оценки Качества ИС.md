# 📋 Техническое Задание & Архитектура

> [!INFO] Статус
> Версия: 2.0 | Приоритет: Высокий | Дата: 17.05.2026

## 🎯 Ключевые решения
| Компонент | Решение | Обоснование |
|-----------|---------|-------------|
| Расчёты | ✅ Только Python (Backend) | Исключает рассинх с БД, упрощает тестирование |
| Generated Columns | ❌ Не используются | `formula_type` находится в другой таблице |
| Soft Delete | ✅ `is_deleted` + `deleted_at` | Сохранение истории для аудита |
| Экспертные суждения | ✅ Append-only таблица | Банковский compliance |
| AI-модуль | ✅ Ollama + retry + валидация | Защита от галлюцинаций, timeout 120s |

## 🏗️ Технологический стек
```yaml
Backend: Python 3.10+, FastAPI (async), SQLAlchemy 2.0 Async, Pydantic v2, Alembic
Database: PostgreSQL 14+
Queue: Celery + Redis
Frontend: React 18, TypeScript (strict), Ant Design v5, Apache ECharts, Redux Toolkit
Auth: JWT (Access/Refresh), LDAP (Feature Flag), bcrypt
DevOps: Docker Compose, GitLab CI, Feature Flags (YAML + ENV)
```

## 📊 Бизнес-правила
- **Период**: `Q{1-4}-{YYYY}` (уникально на `system_id`)
- **Формулы**: 
  - `DIRECT`: `X = A/B`
  - `INVERSE`: `X = 1 - (A/B)`
- **Уровни**: `≥81% Высокий` → `≥61% Выше среднего` → `≥41% Средний` → `≥21% Ниже среднего` → `>0% Низкий` → `0% Невозможно измерить`
- **Валидация**: `B ≠ 0`, `A ≥ 0`, URL-проверка артефактов

## 🔐 Ролевая модель
| Роль | Доступ |
|------|--------|
| `TEST_ANALYST` | Ввод метрик, черновики, загрузка Excel |
| `QUALITY_MANAGER` | Экспертные суждения, утверждение, отчёты |
| `ADMIN` | Управление ИС, пользователями, справочниками |
| `EXECUTIVE` | Dashboard, AI-резюме, экспорт |

> [!WARNING] Безопасность
> - Пароли хешируются `bcrypt(rounds=12)` даже в демо-режиме
> - LDAP-кэш: TTL 3600s в Redis
> - Аудит: все мутации логируются в `audit_log`

## ⚙️ Расчетное ядро (`services/calculation_engine.py`)
```python
from decimal import Decimal, ROUND_HALF_UP
from app.schemas.assessment import QualityLevel

def calculate_metric_value(a: float, b: float, formula_type: str) -> tuple[float, QualityLevel]:
    if b == 0: return 0.0, "Невозможно измерить"
    raw = (a / b) if formula_type == "DIRECT" else (1 - (a / b))
    x = round(max(0.0, min(1.0, raw)), 4)
    p = x * 100
    level = ("Высокий уровень" if p >= 81 else
             "Уровень выше среднего" if p >= 61 else
             "Средний уровень" if p >= 41 else
             "Уровень ниже среднего" if p >= 21 else
             "Низкий уровень" if p > 0 else "Невозможно измерить")
    return x, level
```

## 🔐 JWT & Auth (`core/security.py`)
```python
from passlib.context import CryptContext
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto", bcrypt__rounds=12)

def verify_password(plain: str, hashed: str) -> bool: return pwd_context.verify(plain, hashed)
def hash_password(plain: str) -> str: return pwd_context.hash(plain)
```

## 📊 Excel-процессор (`services/excel_processor.py`)

- Возврат: `{"success": [...], "errors": [...], "warnings": [...]}`

## 🧮 Клиентский калькулятор (`shared/utils/calculator.ts`)
```typescript
export const calculateMetricValue = (a: number, b: number, formulaType: "DIRECT"|"INVERSE") => {
  if (b === 0) return { x: 0, level: "Невозможно измерить" };
  let raw = formulaType === "DIRECT" ? a / b : 1 - (a / b);
  const x = Math.round(Math.max(0, Math.min(1, raw)) * 10000) / 10000;
  const p = x * 100;
  const level = p >= 81 ? "Высокий уровень" : p >= 61 ? "Уровень выше среднего" : 
                p >= 41 ? "Средний уровень" : p >= 21 ? "Уровень ниже среднего" : 
                p > 0 ? "Низкий уровень" : "Невозможно измерить";
  return { x, level };
};
```

# 🐳 Docker Compose & GitLab CI

## 📦 `docker-compose.yml`
```yaml
services:
  postgres:
    image: postgres:14-alpine
    environment: { POSTGRES_DB: asok_is, POSTGRES_USER: asok_user }
    healthcheck: { test: ["CMD-SHELL", "pg_isready -U asok_user -d asok_is"] }
  backend:
    build: ./backend
    ports: ["8000:8000"]
    volumes: ["./backend:/app", "/app/__pycache__"]
    depends_on: { postgres: { condition: service_healthy } }
  frontend:
    build: ./frontend
    ports: ["3000:3000"]
    volumes: ["./frontend:/app", "/app/node_modules"]
  ollama:
    image: ollama/ollama:latest
    profiles: ["ai"]
```

## 🔄 GitLab CI (`.gitlab-ci.yml`)
```yaml
stages: [validate, test, build, deploy]
test-backend-unit:
  image: python:3.11-slim
  script: [cd backend, poetry install --with dev,test, pytest tests/unit/ -v --cov=app]
  coverage: '/TOTAL.*?(\d+)%/'
deploy-staging:
  stage: deploy
  script: [ssh deploy@staging "cd /opt/asok && docker-compose pull && docker-compose up -d"]
  rules: [{ if: $CI_COMMIT_BRANCH == "main" }]
```

> [!TIP] Секреты
> Храните в GitLab CI/CD Variables (masked, protected). Не коммитьте `.env`!

## 🛠️ Как быстро импортировать в Obsidian

1. Создайте папку `АСОК_ИС`
2. Внутри создайте подпапки: `00_Архитектура`, `01_Backend`, `02_Frontend`, `03_Инфраструктура`, `04_Настройка_Среды`, `99_Приложения`
3. Скопируйте каждый блок выше в файл с соответствующим именем (убедитесь, что расширение `.md`)
4. Откройте Obsidian → `Settings` → `Files & Links` → `New link format`: `Wikilinks`
5. Перезагрузите хранилище (или откройте папку как vault)
6. Готово! Все `[[ссылки]]`, `#теги` и `> [!callouts]` будут работать нативно.

💡 **Рекомендуемые плагины для Obsidian:**
- `Dataview` (для таблиц и агрегации задач)
- `Tasks` (управление чеклистами разработки)
- `Excalidraw` (рисование архитектурных схем поверх текста)
- `Templater` (генерация новых файлов по шаблону)

Если нужно, могу сгенерировать `.zip` архив с готовой структурой папок и файлов или настроить `dataview`-запросы для отслеживания статуса разработки. Напишите, что приоритетнее! 🚀
