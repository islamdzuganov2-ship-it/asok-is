## 2. Объект, среда, подход

- **Объект:** АСОК ИС — оценка качества ИС по ISO/IEC 25010 (ГОСТ Р 25010), методика МК_8.1.
- **Среда:** Docker-compose (`backend` healthy, `postgres`/`redis` healthy, `frontend`, `celery`).
  Прогон API — `http://localhost:8000/api/v1`; юнит — `pytest` внутри контейнера `asok_backend`.
- **Подход:** функциональное тестирование (позитив/негатив), серый ящик; проверка расчётных
  формул, ролевых ограничений (SoD), сквозного governance-цикла, контрактов дашбордов,
  безопасности загрузок, LLM-подсистемы. Артефакты: [[Тест-сценарии_АСОК_ИС_2026-06-30]].

## 4. Результаты

- **Юнит-тесты:** `26 passed` (pytest).
- **Интеграционные (API):** `25 PASS / 0 FAIL`.
- Ключевые подтверждённые сценарии:
  - Расчёт X: DIRECT `80/100→0.8`, INVERSE `20/100→0.8`, `b=0→0.0` «Невозможно измерить»,
    отрицательные значения → 422.
  - SoD: аналитик не может создать риск (403), топ-менеджмент может (201), QM архивирует (200).
  - **Полный governance-путь:** новая ИС → период → заполнение 31 подхарактеристики →
    `finalize` → `COMPLETE` (`filled=31`); неполная оценка → 409.

> Примечание: при первичном прогоне 11 кейсов показали ложный FAIL из-за кодировки
> тела запросов в PowerShell 5.1 (кириллица в JSON ломала enum-валидацию). После отправки
> тела как UTF-8 — все кейсы PASS. Это **артефакт тест-харнесса, а не дефект продукта**
> (подтверждено: те же операции через UTF-8 проходят 201/200).
