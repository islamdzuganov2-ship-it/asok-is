# АСОК ИС — Как работает встроенная LLM (живая демонстрация) · 2026-06-30

> Демонстрация выполнена на живом стенде. Исходная модель `asok-model.gguf` (Qwen3.5, arch
> `qwen35`) не загружается (DEF-01); для демонстрации развёрнута совместимая
> **Qwen2.5-0.5B-Instruct Q4_K_M** (arch `qwen2`) — инференс работает.

## 1. Архитектура (как устроено)

- **In-process, on-prem, без внешних сервисов.** Модель в формате **GGUF** загружается прямо
  в процесс backend через **llama-cpp-python** (llama.cpp). Нет Ollama, нет сетевых вызовов —
  важно для банковского контура.
- Код: `backend/app/services/llm_service.py`. Параметры — `backend/app/core/config.py`
  (`LLM_*`). Точка использования — управленческий дашборд
  `backend/app/api/v1/reports.py::get_executive_dashboard`.
- Ленивая потокобезопасная загрузка; результат кэшируется по `hash(метрики+риски)`.

## 2. Конвейер генерации (пошагово)

```
Дашборд (reports.py)
  ├─ агрегирует метрики периода: "характеристика | метрика | %"
  ├─ берёт релевантные записи из БАЗЫ РИСКОВ по просевшим характеристикам (grounding-контекст)
  └─ llm_service.generate_summary(system, period, metrics_block, known_risks)
        ├─ строит prompt + строгий SYSTEM_PROMPT (роль ИТ-директора, формат, запрет домыслов)
        ├─ complete() → llama.cpp (temperature=0.1, top_p=0.9, max_tokens≈220)
        ├─ GROUNDING-проверка: все «%» в ответе обязаны быть во входных данных
        │     └─ если есть «выдуманный» % → ответ заменяется честным grounded-fallback
        └─ кэш → aiInsights (поле дашборда)
```

**Три уровня защиты от галлюцинаций** (ключевое требование ТЗ):
1. Системный промпт — «использовать только переданные числа, не домысливать».
2. Детерминизм — `temperature=0.1`.
3. Пост-проверка grounding — арифметический фильтр процентов (см. демо §5).

## 3. Живой статус модели (`GET /api/v1/reports/llm-status`)
```json
{"enabled":true,"available":true,
 "model_file":"qwen2.5-0.5b-instruct-q4_k_m.gguf",
 "model_path":"models/llm/qwen2.5-0.5b-instruct-q4_k_m.gguf","temperature":0.1}
```
`available:true` → UI-переключатель «Моки ↔ LLM» показывает зелёный индикатор готовности.
Загрузка модели: **0.6 c** (0.5B); первый инференс — секунды.

## 4. Реальный инференс через продуктовый код (`llm_service.generate_summary`)

**Вход** (как формирует дашборд):
```
Удобство использования | средняя по ИС | 56%
Надёжность | средняя по ИС | 62%
Защищённость | средняя по ИС | 71%
+ риски из базы рисков (обоснование)
```
**Выход модели (реальный, 6.4 c):** управленческое резюме на русском — перечисление метрик,
привязка к рискам из базы (регрессионные автотесты; профилирование/индексация БД) и выводы.
Все числа соответствуют входу (grounding пройден).

**Живой HTTP-эндпоинт `GET /reports/executive-dashboard` (20.3 c, 9 характеристик):**
вернул `aiInsights`, сгенерированный встроенной LLM, со значениями 56–61% — строго из входных
данных (`globalHealthScore=59.76`). Последующие вызовы — мгновенно (кэш).

> Замечание о качестве: 0.5B — «ультралёгкий» режим (по ТЗ v10), стиль простоват и
> многословен. Для продуктива рекомендуется **Qwen2.5-1.5B-Instruct Q4_K_M** (лучше русский,
> та же стандартная архитектура `qwen2`).

## 5. Защита от галлюцинаций — живой тест

| Сценарий | Поведение | Итог |
|---|---|---|
| Модель «придумала» 99% (нет во входе) | лог `LLM упомянула проценты вне входных данных ['99'] — заменяю на честный fallback`; ответ заменён | ✅ 99% отсутствует |
| Модель вернула только валидные % (56/62/71) | принят как есть | ✅ |
| Модель недоступна (`complete→None`) | честный grounded-fallback (худшая метрика «Удобство 56%») | ✅ без падений |
| Нет данных | «данные отсутствуют — автоматический вывод не сформирован» | ✅ честно |

Подтверждается юнит-тестами `backend/tests/test_llm_service.py` (6/6 PASS) и живым прогоном.

## 6. Связь с дефектом DEF-01 и как переключать модель

- **Причина DEF-01:** `asok-model.gguf` = Qwen3.5, метаданные GGUF `general.architecture=qwen35`
  — нестандартная архитектура, не загружается ни одной стабильной сборкой llama.cpp.
- **Решение (применено для демо):** рядом положена `models/llm/qwen2.5-0.5b-instruct-q4_k_m.gguf`;
  backend переключён на неё через `docker-compose.override.yml`
  (`LOCAL_LLM_MODEL_FILE=qwen2.5-0.5b-instruct-q4_k_m.gguf`). Обратимо: удалить override-файл и
  `docker compose up -d backend`.
- **Рекомендация для продуктива:** штатная модель Qwen2.5-1.5B-Instruct Q4_K_M
  (`asok-model.gguf`), либо обновить рантайм до `llama-cpp-python>=0.3.x` для `qwen3`
  (arch `qwen35` всё равно требует корректной конвертации модели).

## 7. Параметры (`config.py` / `.env`)
| Переменная | Значение | Назначение |
|---|---|---|
| `LLM_ENABLED` | true | вкл/выкл LLM |
| `LOCAL_LLM_MODEL_DIR` / `_FILE` | `models/llm` / `qwen2.5-0.5b-instruct-q4_k_m.gguf` | путь к модели |
| `LLM_N_CTX` | 4096 | контекст |
| `LLM_TEMPERATURE` | 0.1 | детерминизм/честность |
| `LLM_MAX_TOKENS` | 220–320 | длина ответа |
