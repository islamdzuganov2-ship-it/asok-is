# АСОК ИС — Оценка системы, пользовательский путь и проблемные зоны для топ-менеджмента · 2026-06-30

## 1. Полный пользовательский путь (governance-цикл) — проверен сквозным тестом

Контур управления качеством по ролевой модели v12. Каждый шаг исполнен и подтверждён на стенде.

```
[Аналитик] вводит исходные данные ──▶ [Система] считает X и уровень ──▶
[Менеджер качества] проф. суждение + мера + база рисков ──▶
[Топ-менеджмент] решение по мере (одобрить/отклонить) ──▶
[Менеджер качества] отчёт о выполнении ──▶ [Топ-менеджмент] статус техдолга/дашборд
```

| # | Роль | Действие | Эндпоинт / экран | Проверено |
|---|---|---|---|---|
| 1 | Аналитик | Логин, заведение ИС, период оценки | `/auth/login`, `/systems`, `/assessments/periods` | ✅ 201/DRAFT |
| 2 | Аналитик | Ввод `val_a/val_b` (ручной/Excel), расчёт X | `/assessments/{id}/metrics`, `/values` | ✅ X=0.8 и т.д. |
| 3 | Система | Маппинг X → уровень (5 уровней) | `calculation_engine` | ✅ корректно |
| 4 | Аналитик | Завершение оценки при полноте 31/31 | `/assessments/{id}/finalize` | ✅ `COMPLETE` |
| 5 | Менеджер качества | Ведение базы рисков (источник обоснований) | `/risks` (C·R·U·Arch) | ✅ 201/200 |
| 6 | Топ-менеджмент | Управленческий дашборд: интегральный показатель, теплокарта, проблемные ИС, AI-резюме | `/reports/executive-dashboard` | ✅ score+heatmap |
| 7 | Аналитик/QM | Аналитический дашборд: распределение по уровням | `/assessments/dashboard` | ✅ levelCounts |

> **SoD-инварианты подтверждены:** аналитик не может создавать риск/меру (403), решение — за
> топ-менеджментом, контроль выполнения — за менеджером качества. Разделение обязанностей работает.

**Вывод по пути:** сквозной цикл «данные → расчёт → завершение → дашборд руководителя» проходит
от начала до конца на чистых данных. Узкое место — на реальных импортированных данных шаг 4
(`finalize`) недостижим из-за номенклатуры (см. DEF-02).

## 2. Оценка системы (scorecard)

Шкала: 🟢 хорошо · 🟡 удовлетворительно (есть риски) · 🔴 требует вмешательства.

| Направление | Оценка | Обоснование |
|---|---|---|
| Архитектура и код | 🟢 | Чистый FastAPI (async), разделение слоёв (models/schemas/services/api), идемпотентные сиды, аккуратная обработка ошибок. |
| Расчётное ядро | 🟢 | Формулы ISO 25010 (DIRECT/INVERSE), клиппинг [0;1], уровни — корректны и покрыты юнит-тестами. |
| Ролевая модель / SoD | 🟢 | 3 канонические роли, `require_role`, SoD-инварианты проверены. |
| Governance-цикл | 🟢 (логика) / 🟡 (данные) | Логика finalize/полноты работает; на реальных данных блокируется номенклатурой. |
| Дашборды и отчётность | 🟡 | Контракты работают; KPI искажается «грязной» номенклатурой и разными единицами (DEF-02, DEF-05). |
| Качество данных | 🔴 | Демо-данные замусорены (дубли характеристик, осиротевшие пары), оценки не финализируемы (DEF-02). |
| LLM / AI-аналитика | 🔴 → 🟡 | Развёрнутая модель `qwen35` не грузится (DEF-01); честный fallback страхует. С рабочей моделью Qwen2.5 — инференс восстанавливается. |
| Безопасность (механизмы) | 🟢 | JWT (тип/подпись/срок), bcrypt-соль, анти-спуфинг загрузок, стоп-старт при дефолтных секретах в проде. |
| Безопасность (контур демо) | 🟡 | DEMO_MODE: встроенные пароли + авто-ADMIN при отсутствии токена; публичные туннели (ngrok/cloudflare) подняты. Для пилота — закрыть. |
| DevOps / наблюдаемость | 🟡 | Контейнеризация полноценная; healthcheck воркера был сломан (исправлено). Нет интеграционных автотестов в CI. |
| Тестируемость / автотесты | 🟡 | Юнит-тесты хорошие (26), API-слой без автотестов (тестировался ручным харнессом). |

**Интегральная оценка:** продукт **функционально работоспособен и архитектурно зрелый для MVP/пилота**,
но **не готов к продуктиву** без устранения трёх блоков: качество данных (DEF-02), LLM-модель (DEF-01),
перевод контура в прод-режим (безопасность) + интеграционные автотесты в CI.

## 3. 🔴 Проблемные зоны — подсветить топ-менеджменту

> Сформулировано в бизнес-терминах. Это «критически важные немногие», а не весь список дефектов.

### ПЗ-1. «AI-аналитика» не выполняет реальный инференс на развёрнутой модели 🔴
- **Суть:** заявленная фича «AI-резюме встроенной LLM» сейчас отдаёт не ответ модели, а
  страховочный текст: развёрнутый файл модели (Qwen3.5 9B, arch `qwen35`) технически не
  загружается ни одной стабильной версией движка.
- **Риск для бизнеса:** несоответствие ожиданий на демонстрациях заказчику/регулятору; репутационный
  риск «AI, которого нет».
- **Что сделано:** документация/конфиг приведены к реальности; для рабочего инференса развёрнута
  совместимая модель Qwen2.5 (демонстрация работает). **Решение:** утвердить штатную модель
  (Qwen2.5-1.5B) как стандарт поставки.

### ПЗ-2. Управленческие дашборды строятся на «грязных» данных 🟠→🔴
- **Суть:** при импорте из Excel имена характеристик не приводятся к эталонной модели качества →
  в отчётах двоятся характеристики (напр. «Надежность» и «Надёжность», «Эффективность…» вместо
  «Производительность»), а реальные оценки **нельзя завершить** (`finalize` недостижим).
- **Риск для бизнеса:** руководитель принимает решения по **искажённой** картине качества
  ИТ-ландшафта; невозможно официально «закрыть» период оценки на боевых данных.
- **Решение:** нормализация номенклатуры при импорте + разовая чистка текущих данных (приоритет №1).

### ПЗ-3. Контур развёрнут в демо-режиме с публичным доступом 🟡
- **Суть:** активны встроенные демо-пароли и авто-вход под ADMIN без токена (DEMO_MODE), при этом
  подняты публичные туннели (ngrok/cloudflare). Для банковского контура это недопустимо в проде.
- **Риск для бизнеса:** неавторизованный доступ к данным оценки качества ИС банка.
- **Решение:** перед пилотом — `DEMO_MODE=false`, реальные секреты (стоп-гейт уже встроен),
  отключение демо-учёток, закрытие/ограничение туннелей, журналирование ИБ-событий по ролям.

### ПЗ-4. Незрелость инженерных практик качества 🟡
- **Суть:** нет интеграционных автотестов в CI (API-слой проверялся вручную); критичный сбой
  наблюдаемости (воркер вечно «unhealthy») оставался незамеченным.
- **Риск для бизнеса:** регрессии и тихие отказы фоновых задач (импорт, AI) попадут в прод.
- **Решение:** ввести интеграционные тесты (governance happy-path, RBAC, finalize) и алерты в CI/CD.

## 4. Рекомендованные приоритеты (дорожная карта)

| Приоритет | Действие | Эффект |
|---|---|---|
| P0 | Нормализация номенклатуры импорта + чистка данных (DEF-02) | Достоверные дашборды, рабочий `finalize` |
| P0 | Штатная LLM-модель Qwen2.5-1.5B вместо `qwen35` (DEF-01) | Реальная AI-аналитика |
| P1 | Перевод контура в прод-режим (секреты, демо-учётки, туннели) | ИБ-готовность пилота |
| P1 | Интеграционные автотесты + алерты в CI | Защита от регрессий и тихих отказов |
| P2 | Async-импорт Excel: запись в БД или удаление пути (DEF-04); единицы KPI (DEF-05) | Консистентность UX/контрактов |
