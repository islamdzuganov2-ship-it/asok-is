# АСОК ИС — Тест-сценарии (функциональное тестирование) · 2026-06-30

> Канонический набор функциональных тест-кейсов АСОК ИС. Исполнен на живом стенде
> (Docker-compose) против REST API `http://localhost:8000/api/v1` + юнит-тесты `pytest`.
> Результаты прогона и дефекты — в [[Отчёт_о_тестировании_АСОК_ИС_2026-06-30]] и
> [[Реестр_дефектов_АСОК_ИС_2026-06-30]].

## 1. Объект и охват

| Параметр | Значение |
|---|---|
| Система | АСОК ИС — автоматизированная система оценки качества ИС (ISO/IEC 25010 / ГОСТ Р 25010) |
| Версия (git) | `a49365f` (v6.1) |
| Контур | backend (FastAPI), frontend (React/Ant), PostgreSQL, Redis, Celery, встроенная LLM (llama.cpp/GGUF) |
| Среда | Docker-compose, все сервисы `up` (backend healthy, postgres/redis healthy) |
| Тип тестирования | Функциональное (позитив/негатив), RBAC, расчётное ядро, governance-цикл, дашборды, валидация загрузок, LLM |
| Методика | Чёрный/серый ящик по ТЗ + проверка расчётных формул по ГОСТ-методике (МК_8.1, ISO 25010) |

## 2. Покрываемые требования ТЗ
- Ролевая модель v12: 3 канонические роли (Топ-менеджмент `ADMIN`, Менеджер качества `QUALITY_MANAGER`, Аналитик `TEST_ANALYST`), SoD-инварианты.
- Расчёт коэффициента X (DIRECT `a/b`, INVERSE `1−a/b`), нормирование в [0;1], маппинг в уровни.
- Governance-цикл: ввод данных → суждение/мера → решение → контроль; полнота оценки 31/31 для `finalize`.
- Дашборды (управленческий/аналитический), теплокарта, проблемные системы.
- Импорт Excel (валидация сигнатуры, анти-спуфинг, размер).
- База рисков (CRUD, поиск как источник grounding для LLM).
- Встроенная LLM: статус, честный fallback, защита от галлюцинаций (grounding).

## 3. Методология статусов
`PASS` — фактический результат совпал с ожидаемым. `FAIL` — расхождение (заводится дефект).
Приоритет дефекта: Critical / High / Medium / Low.

- **Шаги:** `POST /auth/login` для `admin/Admin123!`, `manager/Manager123!`, `analyst/Analyst123!`.
- **Ожидание:** 200, роли `ADMIN`, `QUALITY_MANAGER`, `TEST_ANALYST` соответственно.
- **Факт:** роли совпали. **PASS**

#### TC-AUTH-02 — Неверный пароль
- **Шаги:** `POST /auth/login` `admin/WRONG`.
- **Ожидание:** 401 `Invalid credentials`. **Факт:** 401. **PASS**

#### TC-RBAC-01 — Аналитик не может создавать риск
