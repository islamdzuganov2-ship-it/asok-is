## Честное AI-резюме (встроенная LLM, grounding)
Модель (Qwen2.5-0.5B, `available=true`) сгенерировала управленческий вывод за 42.6 c: определила
**Защищённость 37%** как наиболее просевшую и привязала риски (демо-режим/секреты/авто-ADMIN;
отсутствие интеграционных тестов). Все проценты соответствуют входным (grounding пройден,
галлюцинаций нет). Вывод многословен и обрезан по лимиту токенов — ограничение 0.5B-режима;
для прод-качества рекомендована **Qwen2.5-1.5B** (см. DEF-01).

## Governance-петля (роли и SoD)
Меры качества — фронтовый слой (Redux + localStorage). Путь:
1. **Менеджер по качеству** формирует проф. суждение + меру по просевшим (Защищённость,
   Тестируемость) → статус `PENDING_APPROVAL`.
2. **Топ-менеджмент (ADMIN)** — единственный, кто **согласовывает** (одобрить/отклонить).
   Enforced: `MeasureDecisionModal.tsx::canDecide`, `ExcelReportsPage.tsx::canDecide`.
3. **Менеджер по качеству** — единственный, кто **закрывает** меру (контроль выполнения,
   обязательный комментарий). Enforced: `MeasureDecisionModal.tsx::canReportExecution`.
RBAC проверен в коде (гейтинг присутствует в обоих местах). SoD-инвариант соблюдён.

## Варианты улучшения для топ-менеджмента (уровень CIO/CTO/CEO)

### Приоритет 0 — до пилота/прод (CISO/CTO)
- **Закрыть безопасность (37% при BUSINESS CRITICAL — недопустимо для банка).** Вывести из
  демо-режима; секреты в vault + ротация; включить **аудит ИБ-событий** (подотчётность 30%);
  нормальная аутентификация/MFA (35%), убрать авто-ADMIN без токена; закрыть публичные туннели.
  *Риск бездействия:* несанкц. доступ, утечка ПДн, санкции (ГОСТ Р 57580, 152-ФЗ).

### Приоритет 1 — квартал (CTO/CIO)
- **Инженерная зрелость (тестируемость 30%):** интеграционные автотесты + **CI-гейты качества**.
  *Риск:* техдолг растёт быстрее устранения, регресс, рост инцидентов.
- **Наблюдаемость производительности:** APM + нагрузочное тестирование — сделать «неизмеримое»
  измеримым (2 серые зоны). *Тезис для правления:* «нельзя управлять тем, что не измеряешь».
- **Перенести governance в backend:** меры/решения/исполнение сейчас только в localStorage —
  нет серверного аудита, риск потери данных, нет мультипользовательской согласованности.
  Для SoD и прослеживаемости (152-ФЗ) нужен серверный журнал.

### Приоритет 2 — по мере зрелости
- **Надёжность/HA (отказоустойчивость 50%):** failover, MTTR-runbook.
- **Accessibility (40%):** a11y-аудит ключевых сценариев.

### Стратегически (CEO/CIO)
Интегральные **65% (Выше среднего)** — продукт работает и полезен, но **инструмент контроля
качества сам не прошёл собственный порог безопасности**. Решение: не масштабировать на прод-контур
до закрытия Приоритета 0; после — пилот на 2–3 некритичных ИС.
