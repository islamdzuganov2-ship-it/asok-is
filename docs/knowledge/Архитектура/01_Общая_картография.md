# Общая картография

## 1. Слои системы
```
[ Браузер ] ──HTTP──> [ Frontend: Vite/React SPA :3000 ]
                              │  /api/* (прокси Vite)
                              ▼
                       [ Backend: FastAPI :8000 /api/v1 ]
                        ├── PostgreSQL :5432  (данные)
                        ├── Redis :6379       (брокер Celery, кэш)
                        ├── Celery worker     (фоновые задачи: парсинг Excel, AI-резюме)
                        └── LLM in-process    (llama-cpp, models/llm/asok-model.gguf)
```

## 2. Сервисы Docker Compose (`docker-compose.yml`)
| Сервис | Образ/сборка | Назначение | Профиль |
|--------|--------------|-----------|---------|
| `postgres` | postgres:14-alpine | БД | — |
| `redis` | redis:7-alpine | брокер Celery / кэш | — |
| `backend` | ./backend | FastAPI API + LLM in-process | — |
| `celery_worker` | ./backend | фоновые задачи | — |
| `frontend` | ./frontend | Vite dev-сервер + прокси /api | — |
| `tunnel` | cloudflared | случайная публичная ссылка (http2) | `tunnel` |
| `tunnel-named` | cloudflared | статичный домен (TUNNEL_TOKEN) | `named` |
| `tunnel-ngrok` | ngrok | статичный домен ngrok | `ngrok` |
| `webserver` | caddy:2 | прямой хостинг с TLS (asokis.ai), порты 80/443 | `direct` |

> Один источник (same-origin): фронт зовёт относительный `/api/v1`, Vite проксирует на backend
> (`vite.config.ts` → `VITE_PROXY_TARGET`). Поэтому CORS в обычном сценарии не задействован.

## 3. Ключевые потоки данных

### 3.1 Аутентификация
`LoginPage` → `POST /api/v1/auth/login` → `auth.py` (DEMO_USERS только в DEMO_MODE / БД) →
`security.create_access_token` → токен в `localStorage` + `authSlice`. Защита роутов: фронт
`RequireRole`, backend `deps.require_role`.

### 3.2 Ввод данных качества (Аналитик)
`NewAssessmentPage` (создание ИС/метрики/периода) → `MetricsInputPage` (val_a/val_b) →
`PUT /assessments/{id}/metrics` → `calculation_engine.calculate_metric` (X, уровень) → БД.
Альтернатива: `ExcelUploadBlock` → `/excel/import-*` → `excel_importer`.

### 3.3 Контур мер качества (governance, фронт-состояние)
`ManagerDashboard` → `ProfessionalJudgmentModal` → `governanceSlice.addProposal` (localStorage) →
видно топ-менеджменту в `ExecutiveDashboard`/`MeasuresRegistryCard` → `MeasureDecisionModal`
(одобрить/отклонить + смена ответственного/срока) → менеджер отмечает выполнение → `TechDebtCard`.
Состояние мер живёт во фронте (Redux + localStorage), демо-набор — `mockScaleData.SCALE_PROPOSALS`.

### 3.4 Дашборды
- Управленческий (`ExecutiveDashboard`) — моки `mockScaleData.EXECUTIVE_SCALE`; в режиме LLM
  тянет `GET /reports/executive-dashboard` (индекс + AI-резюме).
- Аналитический (`DashboardPage`) — `GET /assessments/dashboard`; при недоступности — `ANALYTICS_SCALE`.
- Менеджерский (`ManagerDashboard`) — `mockScaleData.MANAGER_SCALE_SYSTEMS`.

### 3.5 LLM
`reports.get_executive_dashboard` → `llm_service.generate_summary` (in-process llama-cpp) →
grounding из `risk_base` + анти-галлюцинационная проверка процентов. Нет файла модели → честный fallback.

### 3.6 База рисков
`RiskBasePage` → `/api/v1/risks` (`risk_base.py`: CRUD + `/search`) → таблица `risk_base`.
Источник grounding для LLM.

## 4. Развёртывание
- Локально: `docker compose up -d` → `http://localhost:3000`.
- Публично: `--profile tunnel|named|ngrok|direct` (см. `docs/REMOTE_ACCESS.md`).
- Миграции: Alembic (`001`…`003`); в DEMO старт делает `create_all` + сидинг.
- LLM-модель: `models/llm/asok-model.gguf` (см. `docs/LLM_SETUP.md`).
