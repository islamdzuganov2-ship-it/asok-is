# АСОК ИС — Рефакторинг DashboardPage в три дашборда

Дата: 2026-05-27

## Задача
Переделать единый `DashboardPage.tsx` в три отдельных дашборда по ролям согласно макету.

## Структура файлов

| Файл | Путь | Назначение |
|------|------|------------|
| `AnalystDashboard.tsx` | `frontend/src/pages/dashboard/` | Тест-Аналитик: дерево ISO 25010, формулы, ввод переменных |
| `ManagerDashboard.tsx` | `frontend/src/pages/dashboard/` | Менеджер: таблица метрик + модал суждения |
| `ExecutiveDashboard.tsx` | `frontend/src/pages/dashboard/` | CTO/CEO: Gauge + TOP-3 AI + Heatmap + Burndown |
| `apiSlice.ts` | `frontend/src/store/api/` | RTK Query: 3 query + 3 mutation эндпоинта |
| `App.tsx` | `frontend/src/` | Роутинг + Segmented переключатель ролей |

## Новые API эндпоинты (бэкенд должен реализовать)

- `GET /api/v1/dashboard/executive` → ExecutiveDashboardData
- `GET /api/v1/dashboard/manager` → ManagerDashboardData
- `GET /api/v1/dashboard/analyst` → AnalystDashboardData
- `POST /api/v1/metrics/{id}/judgment` → профессиональное суждение
- `POST /api/v1/metrics/{id}/draft` → черновик метрики
- `POST /api/v1/metrics/{id}/submit` → отправка на проверку

## Ключевые технические решения

- **Gauge ECharts** вместо Donut — визуально точнее соответствует спидометру макета
- **Lazy loading** трёх дашбордов через `React.lazy` + `Suspense`
- **RTK Cache invalidation**: мутации инвалидируют нужные теги (суждение → manager + executive)
- **Авторасчёт метрики**: `SX = 1 – A/B` в реальном времени, без обращений к бэкенду
- **Критические строки** таблицы подсвечиваются CSS `row-critical` (розовый фон)
- **RAG-маркеры** в списке ИС: CheckCircle/MinusCircle/CloseCircle по порогам 70/40
