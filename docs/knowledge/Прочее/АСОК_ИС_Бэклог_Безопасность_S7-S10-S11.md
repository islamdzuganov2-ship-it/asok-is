## S7 — Авторизация на read-эндпоинты `/reports/*`
**Приоритет:** средний · **Норма:** ГОСТ Р 57580 (разграничение доступа).
**Сейчас:** `reports.py` отдаёт дашборд/матрицы без `Depends(get_current_user)` —
в проде (DEMO_MODE=false) данные доступны без аутентификации.
**Сделать:**
- навесить `Depends(get_current_user)` на все эндпоинты `app/api/v1/reports.py`
  (`/executive-dashboard`, `/assessment-period/{id}/matrices`, `/excel-data`, `/llm-status`);
- при необходимости ограничить управленческий дашборд ролями C-level/ADMIN через `require_role`.
**Критерий приёмки:** без токена в проде — 401; в DEMO_MODE поведение не меняется (deps → ADMIN).

## S10 — Журнал ИБ-событий (аудит)
**Приоритет:** средний-высокий · **Норма:** ГОСТ Р 57580 (регистрация событий), 152-ФЗ (расследования).
**Сейчас:** есть модель `app/models/audit.py`, но события не пишутся.
**Сделать:**
- таблица/использование `audit` для событий: вход/выход, изменение оценок (`val_a/val_b`),
  решения по мерам (одобрение/отклонение + комментарий), доступ к ПДн, импорт Excel;
- поля: `actor`, `action`, `object_type`, `object_id`, `ts`, `ip`, `result`;
- неизменяемость (append-only), метки времени UTC;
- middleware/зависимость или сервис `audit_log(...)`, вызовы в ключевых эндпоинтах.
**Критерий приёмки:** перечисленные действия фиксируются; запись нельзя изменить через API.

## S11 — Анти-брутфорс на `/auth/login`
**Приоритет:** средний · **Норма:** ГОСТ Р 57580 (защита от подбора).
**Сейчас:** `/login` без ограничения частоты — возможен перебор паролей.
**Сделать:**
- rate-limit по IP+username (напр. через Redis: окно N попыток / период);
- временная блокировка учётки после K неудач, экспоненциальная задержка;
- лог попыток в аудит (S10).
**Критерий приёмки:** > N неудачных входов → 429/блокировка; успешный вход сбрасывает счётчик.
