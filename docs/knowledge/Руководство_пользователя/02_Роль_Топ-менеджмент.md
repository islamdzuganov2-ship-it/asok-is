# Роль: Топ-менеджмент

> Вы видите общую картину качества ИТ-ландшафта и принимаете решения по мерам. Вход: `admin`.
> Меню: **Управленческий дашборд · Аналитический дашборд · Настройка.**

---

## Управленческий дашборд — главный экран

### 1. Шапка с общим индексом
- **Общий индекс качества ИТ-ландшафта** — крупный «спидометр» (например, 61%) и словесный уровень.
  Это среднее качество по всем ИС: один взгляд — и понятно общее состояние.
- **«Меры на одобрение N»** (бейдж со счётчиком) — **нажмите**, чтобы открыть список мер,
  ожидающих вашего решения. Клик по мере в списке → окно принятия решения (см. ниже).
- **Переключатель «Демо ↔ LLM»** — демо-данные для презентации или живые данные + AI-резюме.

### 2. Топ проблемных ИС — требуют внимания
Три карточки **самых критичных** систем (сначала по уровню критичности, затем по баллу). На карточке:
- тег **AI-резюме**, **балл** (%), тег **критичности** (MISSION/BUSINESS CRITICAL — приглушённые тона);
- название ИС, краткое резюме проблемы и **рекомендация к действию** («→ …»).
- **Клик по карточке** открывает окно: «кто отвечает», «с кого спрашивать», рекомендуемые действия
  и меры менеджера по качеству, ожидающие вашего решения.
- **«Показать все системы →»** — таблица всех 30 ИС (сортировка по критичности и баллу);
  клик по строке открывает то же окно по выбранной ИС.

### 3. Тепловая карта характеристик
- Сетка «ИС × 8 характеристик», цвет ячейки — уровень качества (пастельная шкала).
- По умолчанию показаны **топ-5** самых критичных систем; кнопка **«Раскрыть все (30)»** —
  показать остальные, «Свернуть» — обратно.
- **Зелёная точка над ячейкой** = по этой характеристике есть **мера, ожидающая вашего решения**
  (быстрый визуальный сигнал, где требуется реакция).
- **Клик по строке/ячейке** → окно «кто виноват / действия». **«Детали →»** ведёт на аналитический
  дашборд с полной картой.

### 4. Статус технического долга
- **Выбор периода** — выпадающие списки **Год** и **Квартал** (по умолчанию — все).
- Два индикатора (burndown): **«Выполнено из одобренных»** и **«Закрыто от всех мер в работе»**.
- Четыре **кликабельных счётчика**: «Ожидают решения», «Одобрены и ждут выполнения»,
  «Выполнено», «Просрочено / не выполнено». **Клик по счётчику** открывает список этих мер;
  клик по мере → окно решения.
- Внизу — сводка: «Всего одобрено: X · из них выполнено: Y».

### 5. Реестр мер качества
- Сверху — две карточки-фокуса: **«Просрочено по сроку решения»** и **«Срок решения ≤ 2 дней»**
  (нажмите, чтобы быстро отфильтровать горящие меры).
- **Фильтры:** поиск (название/метрика/ИС), Система, Статус, **Выполнение**
  (Выполнено / Не выполнено / Ожидает выполнения), Срок решения.
- **Сортировка по умолчанию:** сначала ожидающие решения, самые критичные (низкий %),
  с ближайшим сроком. Показываются первые 3, остальное — под **«Показать все (N)»**.
- Клик по мере → окно решения.

## Окно принятия решения по мере
Открывается по клику на любую меру (в реестре, в счётчиках техдолга, в карточке ИС, в списке
«Меры на одобрение»).

**Что показано:** ИС, характеристика, метрика и её %, обоснование (профессиональное суждение
менеджера) и «что ожидается от вас и почему».

**Если мера ожидает решения — ваши действия:**
1. При необходимости **измените ответственного (ФИО), должность и срок** прямо здесь (это право
   только топ-менеджмента, до принятия решения).
2. Впишите **комментарий к решению** (необязательно, но полезно — условия, приоритет).
3. Нажмите **«Одобрить»** или **«Отклонить»**.

**После решения:** в окне видно ваше решение и комментарий. Если мера одобрена, далее по ней
**отчитывается менеджер по качеству** (Выполнено/Не выполнено с пояснением) — вы видите результат,
но сами выполнение не отмечаете.

## Аналитический дашборд (для деталей)
Подробный операционный взгляд: KPI-карточки (кликабельны — раскрывают распределение метрик и
списки ИС), «бублик» распределения по уровням, таблица проблемных ИС, полная тепловая карта
с **липкой шапкой** (при прокрутке названия характеристик остаются сверху). Тег «Демо-данные»/
«Live из БД» показывает источник.

## Настройка
Администрирование системы (фиче-флаги и сервисные параметры).

## Коротко: ваш типовой сценарий
1. Открыли управленческий дашборд → оценили общий индекс и топ проблемных ИС.
2. Бейдж «Меры на одобрение» → разобрали ожидающие меры, по каждой — одобрить/отклонить
   (при необходимости поправив ответственного и срок).
3. Проверили статус техдолга: что выполнено, что просрочено.
4. Спорные места — открыли «Детали» (аналитический дашборд).
