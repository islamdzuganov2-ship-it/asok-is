### ДЕФ-01 · Незащищённые эндпоинты записи: любой может изменить справочные данные
**S1 Блокирующий · P0 · Безопасность · КР-01 · подтверждён на стенде**

**Суть.** Роутеры `systems` и `quality` не имеют **ни одной** проверки доступа, и глобальной зависимости на `include_router` тоже нет.

**Доказательство (прогон 2026-08-15):**

| Запрос | Токен | Код | Смысл |
| :--- | :--- | :---: | :--- |
| `POST /api/v1/systems` | нет | **201** | Создана запись `ANON_PROBE` в реестре ИС (удалена после проверки) |
| `POST /api/v1/systems` | аудитор | **201** | Роль только для верификации создала систему |
| `DELETE /api/v1/metrics/999999` | нет | **404** | Обработчик достигнут — при реальном ID запись была бы удалена |
| `POST /api/v1/metrics/` | нет | **422** | Обработчик достигнут |
| `PUT /api/v1/metrics/999999` | нет | **404** | Обработчик достигнут |

**Почему S1.** `metric_catalog` — справочник модели качества ISO 25010, на который опираются **все** оценки. Анонимное удаление строки каталога делает исторические оценки нерасчётными. Дефект **не зависит от `DEMO_MODE`** — это отсутствующая зависимость, поэтому сохраняется и в продуктиве.

**Файлы.** `backend/app/modules/systems/router.py` (3 эндпоинта), `backend/app/modules/quality/router.py` (4 эндпоинта).

**Исправление.**
1. `Depends(require_permission("systems.edit"))` на `POST /systems`; чтение — `view.assessments`/`view.reports`.
2. `Depends(require_permission("quality.catalog.edit"))` на `POST/PUT/DELETE /metrics`; добавить право в каталог `iam/permissions.py`.
3. Тест-страж: перебрать все маршруты `app.routes` и потребовать, чтобы у каждого была зависимость гейта, кроме явного белого списка (`/auth/login`, `/auth/refresh`, `/health`, `/`).

### ДЕФ-02 · Демо-режим отдаёт права ADMIN без токена и при поддельном токене
**S1 Блокирующий · P0 · Безопасность · КР-06 · подтверждён на стенде**

**Суть.** `backend/app/modules/iam/deps.py:19–48` — при `DEMO_MODE=true` отсутствующий **и невалидный** токен молча превращаются в пользователя `demo` с ролью `ADMIN`.

**Доказательство:** `GET /api/v1/systems` без токена → **200 + реальные данные**; с подписью `eyJhbGciOiJIUzI1NiJ9.FORGED.SIG` → **200 + реальные данные**.

**Почему S1.** `DEMO_MODE` по умолчанию `True`. Стенд публикуется наружу через Cloudflare Tunnel (БТ-500…503), домен `asokis.ai` разрешён в CORS. Любой, кто знает адрес туннеля, получает административный доступ. Вторичный эффект: невалидный токен не возвращает 401, фронт не отправляет на релогин — маскируются ошибки аутентификации.

**Исправление.**
1. Разделить флаги: `DEMO_MODE` (демо-данные) и `DEMO_AUTH_BYPASS` (обход аутентификации, по умолчанию `false`).
2. **Невалидный/просроченный токен — всегда 401**, даже при включённом обходе. Обход допустим только при полностью отсутствующем заголовке.
3. Предупреждение в лог на каждый обойдённый запрос + видимый баннер в UI.
4. Запретить поднятие туннеля при включённом обходе (проверка в compose-профиле).

### ДЕФ-03 · Alembic не применяется; в продуктиве схема БД не создаётся
**S1 Блокирующий · P0 · Развёртывание · КР-17 · БТ-507**

### ДЕФ-04 · Первый запрос управленческого дашборда блокируется на ~10 минут
**S1 Блокирующий · P0 · Производительность · КР-13 · подтверждён на стенде**

**Суть.** `GET /api/v1/reports/executive-dashboard` после старта backend не отвечает: замер с лимитом 120 с завершился таймаутом (`HTTP=000`), фактический ответ пришёл примерно через 10 минут. Повторные запросы — **0.45 с**, четыре параллельных — **0.60–0.71 с**.

**Причина.** Первый вызов инициирует холодную загрузку модели `gemma-3-12b-it-Q4_K_M.gguf` (**6962 МБ**) с диска под глобальной `threading.Lock` (`modules/llm/service.py:57`). Бюджета времени нет (`LLM_TIMEOUT_S` в конфигурации отсутствует), ограничения очереди нет.

**Почему S1.** Это **главный экран топ-менеджмента** (БТ-180). Первый пользователь после каждого рестарта видит зависшую страницу без индикации. Любой рестарт (в т.ч. вызванный `--reload`, ДЕФ-06) возвращает проблему.

**Исправление.**
1. `LLM_TIMEOUT_S` с честным детерминированным fallback (RES-03).
2. Прогрев модели в фоне при старте (`lifespan`), эндпоинты до готовности отвечают детерминированным вариантом.
3. Ограничение очереди на блокировку: fail-fast `503` вместо неограниченного ожидания (RES-05).

### ДЕФ-05 · У контейнеров нет лимитов памяти и CPU
**S1 Блокирующий · P0 · Ресурсы · КР-09 · RES-01 · подтверждён на стенде**

**Исправление.** `deploy.resources.limits` (memory/cpus) для `backend` и `celery_worker` в `docker-compose.yml`; тест `test_compose_limits.py` (уже написан на ветке `perf/RES-01-05-…`).

### ДЕФ-06 · `--reload` в продуктовой команде при резидентной модели
**S1 Блокирующий · P0 · Ресурсы · КР-10 · RES-08 · подтверждён на стенде**

**Доказательство:** `docker inspect asok_backend --format '{{join .Config.Cmd " "}}'` → `uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload`.

**Почему S1.** `--reload` держит два процесса и перезапускает воркер при любом изменении файла — вместе с ним заново загружаются 7 ГБ весов (ДЕФ-04, ~10 минут недоступности). Это и есть механизм, который заказчик наблюдал как «утечку памяти» (БТ-520): не утечка, а удвоение резидента и повторные загрузки.

**Исправление.** Убрать `--reload` из `docker-compose.yml`; оставить только в `docker-compose.override.yml` для разработки без резидентной модели.
