## Что требует решения прямо сейчас

Семь блокирующих дефектов. Все подтверждены замерами на живом стенде, не предположения.

| ID | Суть | Доказательство |
| :--- | :--- | :--- |
| **ДЕФ-01** | Любой может создать систему и удалить метрику из каталога ISO 25010 — у роутеров `systems` и `quality` нет проверок доступа | `POST /systems` без токена → **201**, запись создана (удалена после проверки) |
| **ДЕФ-02** | В демо-режиме API отдаёт права ADMIN без токена и при поддельном токене | `GET /systems` с подписью `FORGED.SIG` → **200 + данные** |
| **ДЕФ-03** | Alembic не вызывается; при `DEMO_MODE=false` схема БД не создаётся вовсе | В команде backend только `uvicorn`; 12 миграций не выполняются |
| **ДЕФ-04** | Первый запрос управленческого дашборда висит ~10 минут | Замер: таймаут на 120 с; повторный вызов — 0.45 с |
| **ДЕФ-05** | У контейнеров нет лимитов памяти и CPU | `Memory=0 NanoCpus=0`; backend занимает **6.21 ГиБ из 7.7 ГиБ** |
| **ДЕФ-06** | `--reload` в продуктовой команде при резидентной модели 7 ГБ | `docker inspect` → `uvicorn … --reload` |
| **ДЕФ-07** | Celery загрузит вторую копию весов | `printenv LLM_ENABLED` в `asok_celery` → `true` |

ДЕФ-04…ДЕФ-07 вместе объясняют то, что заказчик описывал как «утечку памяти» (БТ-520): это не утечка, а резидентная модель без потолка, удвоенная `--reload` и вторая копия в воркере.

Ещё два P0 — процессные: **ДЕФ-10** (роль «Исполнитель» готова, но зависла на ветке) и **ДЕФ-13** (четыре ветки не влиты, включая `CLAUDE.md` с политикой обязательного PR — политика не действует, потому что сама не была влита).

1. **Спринт 0 (1–2 дня)** — девять P0. Отдельный небольшой PR на каждый пункт.
2. **Спринт 1 (~неделя)** — 15 P1: темизация и UI, ресурсы, архитектурные тесты-стражи.
3. **Спринт 2** — 12 P2: функциональные пробелы и документация.

Условие приёмки любого P0: **автотест, который падал до исправления** (перечень — раздел 8 [реестра дефектов](07_Реестр_дефектов.md)).
