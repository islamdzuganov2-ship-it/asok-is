## Почему это не удалено автоматически

Модели — бинарные файлы вне git (`.gitignore`), и их удаление необратимо: повторная
загрузка 8-гигабайтного файла может быть недоступна в закрытом контуре банка. Поэтому
решение о зачистке принимает владелец стенда, а не скрипт.

## Порядок зачистки

```bash
cd models/llm && ls -la *.gguf
```

Убедиться, что `LOCAL_LLM_MODEL_FILE` в `docker-compose.override.yml` указывает на
остающуюся модель, затем удалить лишние файлы и перезапустить стек:

```bash
docker compose restart backend celery_worker
```

Проверка после перезапуска — `GET /api/v1/reports/llm-status`: поля `available: true` и
`profile.file_name` должны показывать ожидаемую модель.

## Регламент на будущее

1. В каталоге держим **не больше трёх** файлов: рабочая модель, её проектор (если нужен),
   одна лёгкая модель для проверок.
2. Новая модель кладётся на замену, а не в дополнение: система модель-агностична
   (`LOCAL_LLM_MODEL_FILE=auto` берёт новейший `*.gguf`), поэтому забытый крупный файл
   молча станет рабочим при следующем перезапуске.
3. Перед добавлением модели — проверить свободное место: лимит памяти контейнера
   `backend` равен 7000 МиБ (RES-01), модель крупнее в него не поместится.
