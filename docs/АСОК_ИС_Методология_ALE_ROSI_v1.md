# АСОК ИС — Методология оценки стоимости риска и эффективности мер (ALE / ROSI)

> **Версия:** 1.0 · **Дата:** 2026-09-25 · **Код задачи:** RE-22 (BL-007)
> **Статус:** действующий нормативный документ методологии. Сверен с реализацией движков
> (`backend/app/modules/econ/economics.py` и сервисный слой) на коммите этой ветки; все числа
> сквозного примера (§12) получены прогоном самого движка, а не вручную.

## 0. Назначение и границы

Документ описывает **способ** количественной оценки последствий низкого качества информационной
системы (ИС) и выбора управленческого решения по нему: от измеренного значения подхарактеристики
качества по ГОСТ Р ИСО/МЭК 25010-2015 до денежной оценки риска, решения «устранить / компенсировать /
принять», маршрута его утверждения, контроля исполнения и подтверждённого эффекта.

Три назначения:

1. **Воспроизводимость между аналитиками.** Одинаковые входные данные дают одинаковый результат;
   каждый параметр либо фиксирован методикой, либо хранится в справочнике и виден в интерфейсе.
2. **Защитимость перед CFO/CTO.** Каждое число раскладывается до исходных данных (§11 —
   инвариант «не показываем число, о котором нельзя спросить “почему столько”»).
3. **Описание способа для правовой охраны.** ТЗ-23 §7 помечает этот документ критичным для
   патентной заявки: без описанной методики способ нечем обосновать в формуле изобретения. §13
   выделяет существенные признаки способа в последовательности шагов.

Границы: документ не заменяет ТЗ риск-экономического контура (что строится) и ТЗ-19 (управленческий
контур) — он фиксирует **процедуру расчёта**. Интерфейс, роли и права — в соответствующих ТЗ.


Каждое звено — отдельный шаг §3–§10; результат шага — вход следующего.

## 3. Шаг 1. Оценка качества ИС

**3.1. Значение метрики.** `X = A / B` (прямая формула) либо `X = 1 − A / B` (обратная), с
ограничением в [0; 1]. Уровень метрики по X: ≥ 0,81 — высокий, ≥ 0,61 — выше среднего,
≥ 0,41 — средний, ≥ 0,21 — ниже среднего, иначе низкий (`quality/calculation.py`).
Метрика «невозможно измерить» не приравнивается к нулю и требует причины.

**3.2. Балл ИС** — одноуровневая свёртка по весам ГОСТ (вес подхарактеристики уже включает вес
характеристики, повторно не умножается):

```
Балл_ИС = Σ(w_i × X_i) / Σ(w_i)       по измеренным подхарактеристикам i
покрытие = Σ(w измеренных) / Σ(w всех)
```

Неизмеримые подхарактеристики выпадают из обеих сумм (перенормировка), а доля покрытия
показывается отдельной цифрой — одна цифра не несёт двух смыслов (`quality/scoring.py`).

**3.3. Балл портфеля** — критичность работает только на этом уровне:

```
Балл_портфеля = Σ(k_s × Балл_ИС_s) / Σ(k_s),    k = 3 (Mission Critical) / 2 (Business Critical) / 1 (Business Operational)
```

**3.4. Глубина оценки** (RE-19). Обязательный набор подхарактеристик зависит от класса ИС и
выводится из весов ГОСТ: Mission Critical — все 31; Business Critical — «профильные» (вес ≥ 3) и
скрининг, 19; Business Operational — скрининг, по одной самой весомой на характеристику, 8
(`quality/depth.py`). Оценка завершается, когда заполнен обязательный набор.

## 4. Шаг 2. Несоответствие

Несоответствие фиксируется на подхарактеристике с уровнем и типом доказательства:

| Уровень | Вклад в балл | Смысл |
|---|---|---|
| MINOR (незначительное) | 75 % | в пределах допуска деградации |
| MAJOR (существенное) | 40 % | норматив нарушен, БП работает |
| CRITICAL (критическое) | 0 % | норматив нарушен, БП под угрозой; на Mission Critical — **блокирующее** |

Тип доказательства (RE-21): A — инструментальное, B — статистика инцидентов, C — артефакты кода,
D — документальное, E — экспертное. При конфликте измеримое (A/B/C) приоритетнее экспертного.

Статус-цикл: Выявлено → Оценено (₽) → Решение принято → Мера назначена → В работе → Исполнено →
Верифицировано. «Верифицировано» ставит только аудитор, не исполнитель и не оценщик (SoD).

## 5. Шаг 3. Стоимость единичной реализации сбоя C_ТС

```
C_ТС = C_восст + C_простой + C_вторичные
```

**5.1. Стоимость восстановления** — по линиям сопровождения L1–L3:

```
C_восст = Σ_линия  стоимость_линии(T_линия)
```

* Ставка выбирается по связке **ИС × линия × исполнитель** (внутренняя команда или вендор), с
  откатом: ИС+исполнитель → глобальная+исполнитель → ИС+любой → глобальная+любой.
* Внутренняя ставка = `ФОТ_мес × K_накладных / фонд_времени_мес` (K_накладных — справочник, по
  умолчанию 1,6).
* K_время — коэффициенты самой ставки: будни 08:00–20:00 — 1,0; вечер/ночь — `k_evening`
  (1,5); выходные — `k_weekend` (2,0).
* **Только для вендора:** часы округляются вверх до кванта биллинга
  `T_к_оплате = ⌈T × 60 / квант⌉ × квант / 60`; внутри остатка месячного пакета часы оплачиваются
  по ставке пакета, сверх — по сверхлимитному тарифу:
  `стоимость = (min(T, остаток) × ставка + max(0, T − остаток) × сверхлимит) × K_время`.
  Остаток пакета = пакет − часы, уже израсходованные в том же календарном месяце по той же ИС.

**5.2. Стоимость минуты простоя БП** (RE-02) — метод хранится вместе с числом:

| Метод | Формула | Применимость |
|---|---|---|
| Ресурсный | `N_сотрудников × Ставка_час × K_простоя / 60 × K_наверстывания` (K_простоя 0,6, K_наверстывания 1,3 по умолчанию) | бэк-офис |
| Транзакционный | `выручка_за_период / минуты_работы_БП × доля_процесса` | **только** выручкообразующие (фронтальные) БП |
| Экспертно-ступенчатый | `(нижняя + верхняя) / 2`, диапазон показывается рядом | нет данных для расчёта |

Временной профиль: `C_мин(t) = C_мин_база × φ(t)`, где φ — множитель пика (часы 9–18 по
умолчанию), вне пика и выходных дней.

**5.3. Стоимость простоя:**

```
C_простой = Σ_БП  T_недоступности × C_мин(t_сбоя) × K_влияния × доля_БП_на_ИС
```

**5.4. Деградация** (RE-06). K_влияния считается по типу деградации:

| Тип | K |
|---|---|
| Функциональная | Σ весов недоступных функций / Σ весов всех функций |
| Производительная | ступенчатая шкала по кратности отклика к нормативу: ≤ ×1 → 0; ×2 → 0,2; ×3 → 0,35; ×5 → 0,5; ×10 → 0,8; > ×10 → 1,0 |
| Пропускная | 1 − фактическая / требуемая пропускная способность |

Правило конвертации: деградация с K ≥ 0,7, длящаяся ≥ 15 минут, **учитывается как простой**
в доступности и SLA; прочая деградация входит в стоимость, но не в доступность. Пороги — справочник
`degradation_downtime`.

## 6. Шаг 4. Годовая стоимость риска ALE

```
ARO = число реализаций за окно / длина окна, лет     (окно — itsm_history_months, 12 мес)
      либо экспертная частота, если реализаций нет
SLE = среднее C_ТС по реализациям                     (либо экспертная оценка)
SLE_P90 = перцентиль 90 по C_ТС (линейная интерполяция, при ≥ 3 реализациях)
MaxSLE = максимум C_ТС

ALE_средний = ARO × SLE
ALE_P90     = ARO × SLE_P90       («плохой год» — резерв)
MaxSLE                              (вход вето катастрофичности)
```

Три величины обязательны: одна средняя систематически недооценивает Mission Critical-системы с
тяжёлым хвостом ущерба.

## 7. Шаг 5. Мера и её экономическая эффективность

**7.1. Тип меры.** Устраняющая снимает первопричину: растут балл и ΔScore, падает ALE.
Компенсирующая оставляет причину: балл не растёт, ALE падает за счёт ущерба или вероятности.
Дашборд показывает остаточный риск трёх состояний: без мер / с компенсирующими / со всеми
выполненными мерами (RE-10).

**7.2. ΔALE меры** — по портфелю снимаемых рисков, с долей снятия каждого:

```
ΔALE = Σ_риск  ALE_средний(риск) × доля_снятия(риск, мера)
```

Одна мера, закрывающая несколько рисков, не удваивает эффект: доля снятия задаётся на связи
риск ↔ мера. ΔALE раскладывается на кассовую, отложенную и высвобожденную мощность; в ROSI по
умолчанию входит только кассовая.

**7.3. ROSI** — дисконтированная выгода против полной стоимости владения мерой за горизонт:

```
r_мес     = (1 + r)^(1/12) − 1
Выгода_PV = Σ_{t = t_внедр + 1 … T}  (ΔALE / 12) / (1 + r_мес)^t
Затраты_PV = CAPEX + Σ_{t = 1 … T}  (OPEX / 12) / (1 + r_мес)^t
ROSI = (Выгода_PV − Затраты_PV) / Затраты_PV
```

Лаг внедрения `t_внедр` съедает часть выгоды: эффект начинается после внедрения, а затраты — сразу.
Сравнивается **годовой риск за горизонт против полной стоимости меры**, а не единичный сбой
против меры (§3.1 ТЗ контура). По умолчанию r = 20 %, T = 24 мес (справочник).

## 8. Шаг 6. Решение: вето, вердикт, акцепт

Правило (вето приоритетнее экономики):

```
ЕСЛИ риск регуляторный                          → УСТРАНИТЬ
ИНАЧЕ ЕСЛИ MaxSLE ≥ порог катастрофичности       → УСТРАНИТЬ
ИНАЧЕ ЕСЛИ ROSI > 0                              → УСТРАНИТЬ
ИНАЧЕ ЕСЛИ ALE > риск-аппетит                    → КОМПЕНСИРОВАТЬ
ИНАЧЕ                                            → ПРИНЯТЬ (с подписью и датой пересмотра)
```

Риск-аппетит — по классу ИС (справочник `risk_appetite_by_class`) или на самом риске (берётся
минимальный по портфелю меры). Принятие риска подписывает уровень по матрице акцепта: первый
порог, в который укладывается ALE (по умолчанию ≤ 1 млн ₽ — владелец ИС, ≤ 10 млн ₽ — CIO,
выше — правление/комитет).

## 9. Шаг 7. Маршрут утверждения меры

```
ale_risk   = Σ_риск ALE_средний × доля_снятия                     (тот же портфель, что в ΔALE)
порог      = риск_аппетит_класса_ИС × доля_порога / (w_характеристики / w_средний)
эскалация  = is_blocking ∨ регуляторный ∨ (аппетит не задан ∧ ale_risk > 0) ∨ ale_risk > порог
```

Доля порога — справочник `measure_escalation_threshold_share` (10 %). Вес характеристики понижает
порог для весомых характеристик: одна и та же сумма в рублях эскалируется по «Надёжности» раньше,
чем по «Удобству использования». Ниже порога меру утверждает менеджер по качеству или сам
ответственный (своя мера), выше — топ-менеджмент. Мера без связанного рискового события не
маршрутизируется (исключение — явно помеченные процессные меры).

## 10. Шаг 8–9. Исполнение, цена неисполнения, эффект во времени, верификация

**10.1. Цена неисполнения Ц_ОМ.** При просрочке меры (срок прошёл, мера не выполнена):

* устраняющая: `Ц_ОМ = ale_risk` — годовая стоимость риска, остающегося незакрытым;
* компенсирующая: `Ц_ОМ = Σ C_ТС` по сбоям связанных рисков, случившимся после просрочки, —
  фактический ущерб, который мера должна была гасить.

Фиксируются снимок на момент просрочки (не меняется задним числом) и ежедневный ряд текущего
значения; квартальный вид агрегирует дневные точки, а не пересчитывает заново.

**10.2. Эффект во времени.** Квартальный ряд: до выхода на эффект (дата старта + лаг) чистый эффект
квартала равен нулю; далее `ΔALE_кассовый / 4 − OPEX / 4`; накопленный эффект начинается с −CAPEX.
Квартал окупаемости — первый, где накопленный эффект ≥ 0.

**10.3. Верификация и замыкание.** Исполнитель ставит «Исполнено», аудитор — «Верифицировано» и
подтверждённый ΔScore. Замкнутость контура = доля несоответствий в статусе «Верифицировано».
Метрики руководителей (RE-20) берут ΔALE, зафиксированный при одобрении меры, взвешивают его по
критичности ИС (3/2/1) и считают результативность как долю выполненных мер с подтверждённым
аудитором ΔScore > 0; в режиме «мотивация» засчитывается только подтверждённый эффект.

## 11. Вспомогательные расчёты

**11.1. Гибридные веса подхарактеристик (советчик, RE-15).**

```
α(i)   = max(α_min, N₀ / (N₀ + N(i)))            N(i) — число сбоев с подхарактеристикой i
вес(i) = α(i) × профиль(i) + (1 − α(i)) × доля_i_в_ALE
```

При отсутствии статистики α = 1 и вес равен нормативному профилю: риск с большим экспертным ALE,
но без подтверждённых сбоев, веса не искажает. По умолчанию α_min = 0,3, N₀ = 12.

**11.2. Промышленные данные ITSM (задел RE-23…RE-27).**

* Трудозатраты линии из журнала переназначений: `T_линия = Σ(время на линии) × K_утил`,
  K_утил — медиана отношения «факт / время на линии» на ≥ 30 тикетах с известными трудозатратами
  (0,3 по умолчанию).
* Тикет → ИС: алиас ИС → имя ИС → группа назначения.
* Дубли: тикеты одной ИС в окне 45 минут **от первого** тикета — один сбой; дубли не входят в ARO,
  MTBF и доступность.
* Поправка по APM: медианные сдвиги начала и восстановления сбоя; простой = скорректированное
  восстановление − скорректированное начало, не меньше нуля.

## 12. Сквозной пример

Числа получены прогоном движка `econ/economics.py` на приведённых входах.

**Исходные данные.** ИС «Платёжный шлюз», Mission Critical, риск-аппетит класса 500 000 ₽/год.
БП «Приём платежей» (фронтальный), доля на ИС 1,0: выручка за месяц 43 200 000 ₽, 43 200 минут
работы, доля процесса 0,5; профиль: пик 9–18 ×1,0, вне пика ×0,6, выходные ×0,4.

**Сбой** в среду в 14:00: полный отказ 90 минут. L2 — внутренняя команда 3 ч (ФОТ 200 000 ₽ /
160 ч, K_накладных 1,6). L3 — вендор 1 ч 15 мин: ставка 6 000 ₽/ч, квант 60 мин, пакет 10 ч/мес,
в этом месяце уже израсходовано 9 ч, сверхлимит 9 000 ₽/ч.

| Величина | Расчёт | Итог |
|---|---|---|
| C_мин | 43 200 000 / 43 200 × 0,5; φ(ср 14:00) = 1,0 | 500 ₽/мин |
| C_простой | 90 × 500 × 1,0 × 1,0 | 45 000 ₽ |
| Ставка L2 | 200 000 × 1,6 / 160 | 2 000 ₽/ч |
| L2 | 3 × 2 000 × 1,0 | 6 000 ₽ |
| L3 к оплате | ⌈1,25 × 60 / 60⌉ × 60 / 60 | 2 ч |
| L3 | (1 × 6 000 + 1 × 9 000) × 1,0 | 15 000 ₽ |
| **C_ТС** | 6 000 + 15 000 + 45 000 | **66 000 ₽** |

**Риск** «Отказ балансировщика»: за 12 месяцев четыре реализации с C_ТС 66 000, 40 000,
120 000 и 54 000 ₽.

| Величина | Расчёт | Итог |
|---|---|---|
| ARO | 4 / 1 год | 4 |
| SLE | (66 000 + 40 000 + 120 000 + 54 000) / 4 | 70 000 ₽ |
| SLE_P90 | 66 000 + (120 000 − 66 000) × 0,7 | 103 800 ₽ |
| **ALE_средний** | 4 × 70 000 | **280 000 ₽/год** |
| ALE_P90 | 4 × 103 800 | 415 200 ₽/год |
| MaxSLE | max | 120 000 ₽ |

**Мера** «Резервирование балансировщика N+1» (устраняющая): доля снятия 0,8, CAPEX 150 000 ₽,
OPEX 30 000 ₽/год, лаг внедрения 3 мес; r = 20 %, T = 24 мес.

| Величина | Итог |
|---|---|
| ΔALE | 280 000 × 0,8 = 224 000 ₽/год |
| Выгода_PV (мес. 4–24) | 318 232,38 ₽ |
| Затраты_PV | 199 896,49 ₽ |
| **ROSI** | **+0,592 (+59 %)** → вердикт **УСТРАНИТЬ** |

Контрольный вариант той же меры за CAPEX 400 000 ₽ и OPEX 60 000 ₽/год: Затраты_PV 499 792,99 ₽,
ROSI −0,3633. Вето нет, ALE 280 000 ₽ ниже аппетита 500 000 ₽ → **ПРИНЯТЬ**; при аппетите
200 000 ₽ тот же расчёт дал бы **КОМПЕНСИРОВАТЬ**.

**Маршрут.** ale_risk = 224 000 ₽; вес «Надёжности» 20 при среднем 12,5 → порог
500 000 × 0,10 / 1,6 = 31 250 ₽; 224 000 > 31 250 → **эскалация к топ-менеджменту**.

**Эффект во времени** (одобрение 01.10.2026, выход на эффект 01.01.2027): квартальный чистый
эффект 224 000 / 4 − 30 000 / 4 = 48 500 ₽; накопленный: 2026-Q4 −150 000; 2027-Q1 −101 500;
Q2 −53 000; Q3 −4 500; **Q4 +44 000 — квартал окупаемости 2027-Q4**.

**Цена неисполнения.** Если мера просрочена, Ц_ОМ = 224 000 ₽/год — фиксируется снимком на дату
просрочки и далее ежедневно.

**Деградация (иллюстрация правила).** Производительная деградация с откликом ×3 длительностью
120 минут: K = 0,35 < 0,7 → в стоимость входит, в доступность — нет. Функциональная деградация
9 из 10 функций 40 минут: K = 0,9 ≥ 0,7 и ≥ 15 мин → учитывается как простой.

## 13. Существенные признаки способа

Для формулы изобретения способ выделяется как последовательность действий, выполняемых
вычислительной системой (признаки сформулированы для последующей редактуры патентным
поверенным, не как окончательная редакция):

1. Получают значения метрик подхарактеристик качества ИС и формируют взвешенный балл ИС по весам
   подхарактеристик с перенормировкой на измеренные подхарактеристики и **раздельным показателем
   покрытия измерением**; балл портфеля формируют по весам **классов критичности ИС**, причём веса
   подхарактеристик и веса критичности применяют на разных уровнях свёртки.
2. Определяют **обязательный набор подхарактеристик по классу критичности**, выводя его из весов
   подхарактеристик (полная / профильная / скрининговая глубина).
3. Для каждого технического сбоя вычисляют стоимость единичной реализации как сумму стоимости
   восстановления **по линиям сопровождения с выбором ставки по связке «ИС × линия × исполнитель»**,
   квантом биллинга и учётом остатка пакета часов в календарном месяце, и стоимости простоя
   **через стоимость минуты бизнес-процесса, зависящую от метода расчёта и временного профиля**,
   с коэффициентом влияния, **вычисляемым по типу деградации**.
4. Учитывают деградацию как простой для показателя доступности **только при превышении
   порогов коэффициента влияния и длительности**.
5. Вычисляют годовую стоимость риска в трёх величинах — средней, P90 и максимальной единичной — по
   частоте и стоимостям реализаций.
6. Вычисляют эффект меры как **сумму годовых стоимостей связанных рисков с долями снятия** и её
   ROSI как отношение дисконтированной выгоды **с учётом лага внедрения** к полной стоимости
   владения за горизонт.
7. Формируют вердикт «устранить / компенсировать / принять» по правилу, в котором **вето
   (регуляторное, катастрофичности) приоритетнее экономического критерия**, а выбор между
   компенсацией и принятием определяется риск-аппетитом.
8. Определяют маршрут утверждения меры по **денежному порогу, равному доле риск-аппетита класса
   ИС, делённой на относительный вес характеристики**, с безусловной эскалацией для блокирующих и
   регуляторных случаев.
9. При просрочке меры вычисляют **цену неисполнения по разным формулам для устраняющей и
   компенсирующей меры**, фиксируя снимок на момент просрочки и ежедневный ряд.
10. Подтверждают эффект меры независимой верификацией и используют **зафиксированный на момент
    решения ΔALE** в показателях руководителей.

## 15. Допущения и ограничения

* Эффект меры наступает ступенькой на дату выхода на эффект (без плавного выхода) — заказчик не
  выбрал форму нарастания (В-49); ступенька не завышает раннюю окупаемость.
* Вторичные потери (штрафы, репутация) в C_ТС пока не рассчитываются, а вводятся экспертно на
  уровне риска (SLE_экспертный) — отдельной строкой, чтобы не смешивать с измеренным ущербом.
* Экспертно-ступенчатый C_мин несёт неопределённость диапазона; она показывается рядом с числом.
* Данные ITSM на пилоте не подключены; фаза I (§11.2) даёт тот же расчёт на автовыгрузке без
  изменения формул.
