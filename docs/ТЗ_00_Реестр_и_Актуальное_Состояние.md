### 1.2 Ролевая модель и права (BL-008)

**Ключевое расхождение, устраняемое этим документом:** ТЗ-02 и README описывали
«**три канонические роли**». Фактически в системе **девять** ролей и серверный RBAC
на каталоге прав.

| Параметр | Факт | Источник |
| :--- | :--- | :--- |
| Ролей | **9**: `TEST_ANALYST`, `QUALITY_MANAGER`, `CTO`, `CEO`, `ADMIN`, `RISK_MANAGER`, `AUDITOR`, `EXECUTOR`, `SUPER_ADMIN` | `modules/iam/models.py` (`ALL_ROLES`) |
| Встроенные роли | `ADMIN`, `SUPER_ADMIN` — права вычисляются кодом, матрицей не редактируются | `modules/iam/permissions.py` (`BUILTIN_ROLES`) |
| Каталог прав | **44** права в **семи** группах: «Дашборды», «Разделы», «Администрирование», «Оценка», «Меры», «Риск-экономика», «Система» | `modules/iam/permissions.py` (`PERMISSIONS`) |
| Матрица «роль → права» | таблица `role_permissions`, редактируется только суперадминистратором | `modules/iam/permissions_service.py` |
| Защита от самоблокировки | `SUPER_ADMIN` всегда получает весь каталог мимо матрицы | `permissions_service.py:64` |
| Проверка на сервере | `require_permission` с кэшем | `modules/iam/deps.py` |
| Проверка на клиенте | `RequirePermission` на каждом маршруте (по праву, не по роли) | `frontend/src/App.tsx` |
| Покрытие эндпоинтов правом | **115 из 171** требуют право; 56 закрыты только аутентификацией (справочники, оценки, база рисков — денег не содержат). **Все денежные чтения контура закрыты правом `view.risk_economics`** после ДЕФ-42 (07.09.2026); было 103/68 | `grep "Depends(require_permission"`; разбор — [ТЗ-23 §6](./ТЗ_23_Карта_Реализации.md) |

> Роли `TEST_ANALYST` / `QUALITY_MANAGER` / `CTO` / `CEO` остаются **каноническим ядром**
> процесса оценки; `RISK_MANAGER`, `AUDITOR`, `EXECUTOR` добавлены риск-экономическим контуром
> (RE-17, RE-18) и требованиями заказчика 2026-08; `ADMIN` / `SUPER_ADMIN` — административные.

## 7. Регламент актуализации и синхронизация с Obsidian

1. **Источник истины — `docs/` в репозитории.** Хранилище Obsidian
   `Documents/Obsidian/Islam/АОК ИС/АСОК_ИС/07_ТЗ/` — зеркало, обновляется вслед за `docs/`.
2. Каждое ТЗ несёт блок «Актуализация» со ссылкой на этот документ; расхождение цифр
   разрешается в пользу §1.
3. При изменении кода, затрагивающего §1 (роли, права, модули, эндпоинты, миграции, тесты),
   §1 пересчитывается тем же коммитом.
4. Новые требования получают код по §3; **новые схемы нумерации не заводятся** без внесения
   в §3.
5. Изменения доводятся до `main` через Pull Request (см. `CLAUDE.md`) с зелёными проверками
   `npm run typecheck`, `npm test`, `npm run check:contrast`, `npm run build`.
