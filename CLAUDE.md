# CLAUDE.md — правила работы с репозиторием АСОК ИС

## Политика веток и PR (базовая, обязательная)

**По завершении любой задачи изменения доводятся до `main` через Pull Request.** Это дефолт, а не
исключение.

1. **Работа — только в отдельной ветке** (feature-ветка или git worktree). Прямые коммиты и пуши
   в `main` не выполняются.
2. **Перед PR все конфликты с `main` должны быть разрешены** — ветка сливается/ребейзится на
   актуальный `origin/main`, конфликты решаются с сохранением обеих сторон (ничего не теряем).
3. **Перед PR — зелёные проверки** (см. ниже). PR с падающими проверками не открывается.
4. **PR обязателен по завершении задачи.** Даже если задача маленькая — результат оформляется
   как PR в `main`, а не мёржится напрямую. Финальный мёрж PR в `main` — за пользователем/ревью.
5. **Не мёржить в `main` чужие/экспериментальные ветки** без ревью их содержимого.

### Проверки перед PR (frontend/)

```bash
npm run typecheck        # tsc — 0 ошибок
npm test                 # vitest — все зелёные
npm run check:contrast   # WCAG 2.1 AA — 0 нарушений
npm run build            # прод-сборка проходит
```

Бэкенд (при изменениях): `pytest` в `backend/` (в Docker-стеке).

### Разрешение конфликтов

- Сохранять **обе** стороны, если изменения независимы (новые роли/маршруты/пункты меню/импорты).
- После резолюции — `git grep '<<<<<<<'` должен быть пустым; затем прогнать проверки выше.
- Тесты/скрипты, завязанные на конкретные значения токенов, обновлять при изменении источника
  истины (например, перевод `BRAND.*` на CSS-переменные потребовал правки `designSystem.test.ts`).

## Политика бэклога ИБ (безопасность)

Все находки и задачи информационной безопасности — включая новые, обнаруженные в ходе
дальнейшей работы, — сначала заносятся в `docs/BACKLOG_ИБ.md` со статусом `queued` и
меткой **«требует дополнительного анализа перед реализацией»**. Задача из этого бэклога
**не реализуется автоматически**: анализ (актуальность, точный объём, риск регресса, что
проверить перед мёржем) и сама реализация начинаются только по явной команде пользователя —
так же, как в `docs/BACKLOG.md` («реализация «по команде»»). Исключение — пункты, уже явно
переведённые пользователем в `in-progress`/`done`. Обоснование и нормативные ссылки —
`docs/SECURITY_AUDIT_RF_2026-09-08.md`.
